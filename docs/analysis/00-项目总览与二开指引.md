## 1. 项目是什么

**紫微斗数排盘系统**，基于倪海夏《天纪》教学体系（三合派正统，明确弃用飞星派工具）。线上站点 **https://metisziwei.com**（ICP 备案渝ICP备2026013379号-1，王多鱼AI 运营）。

仓库一分为二：

| 分支 | 定位 | 内容 |
|---|---|---|
| `main`（13 commits） | **开源版**（GitHub Renhuai123/ziwei-doushu） | 排盘算法 + 格局库 + 古籍 + SEO 知识，无 AI 后端、无运营功能；README 宣称"AI 解读 API 不在开源范围" |
| `feat_0.1`（当前，31 commits） | **运营版**（生产线上） | = main + 18 commits：AI 多 Provider 解读、freemium 订阅分层、AI 多轮对话、名人案例、合盘/对比页、分享图等 |

分支关系：**纯线性**——feat_0.1 只是 main 的后继（merge-base = main HEAD `88194a4`），无分叉。main 停止演进后，运营功能全部叠在 feat_0.1 上。**二开请直接在 feat_0.1 上做**（当前已 checkout）。

**一个反直觉的事实（务必先知道）**：`lib/ziwei/algorithm.ts` 标题写"紫微斗数排盘算法"，但**真正的安星/四化/大限计算全部由 iztro 完成**（`algorithm.ts:72 astro.bySolar(...)`）。自研层只做：亮度 3 档归一、星曜类型映射、空宫借对宫、大限区间匹配（实岁 vs 虚岁口径）、农历独立换算、纯数据产出 `ZiweiChart`。改排盘口径 = 改 iztro 调用参数或 fork iztro，不是改 algorithm.ts。

## 4. 核心业务流（一图流）

```
BirthForm 表单
   │  formToBirthInfo (share.ts:26) — 真太阳时经度校正 + 晚子时次日进位
   ▼
generateChart (algorithm.ts:66) — iztro astro.bySolar 排盘 → ZiweiChart
   ├─▶ detectPatterns (patterns.ts:1018) — 41 识别器 × 5 组 → 格局卡
   ├─▶ computeRadar (radar.ts:79) — 5 维雷达分 → 雷达图
   ├─▶ render react-iztro Iztrolabe — 盘面（chart/cases/chart-compare）
   └─▶ JSON 上行 POST /api/interpret|chat（InsightPanel 发起）
         │  buildChartContext (prompt.ts:30) 整盘文本化 + 倪师 system prompt
         ▼
       多 Provider 流式（llm.ts → agnes 免费 / iztro 官方付费）
         ▼  SSE → lib/sse.ts buildTransformStream 转 {"delta":{"text"}} 协议
         ▼
       InsightPanel 流式渲染（sseBuffer 跨 chunk 拼行）
```

**freemium 分水岭**：`plan=deep`（付费深度解读/对话）强制走 iztro 官方模型并经 `lib/plan.ts` 配额闸门（未订阅/耗尽 → `402 {upgrade:true}`）；`plan=free` 走 agnes 免费链且**排除 iztro**。UI 上 13 个解读维度 = 6 免费 + 7 🔒，AI 对话独立 tab 且整体收费。（详见 02 文档 §4、03 文档 §5。）
