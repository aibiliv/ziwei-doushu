## ① 范围与职责

本层是产品的「命理内核」与「静态知识底座」，分四块：

| 子层 | 目录 | 职责 | 接线状态 |
|---|---|---|---|
| 排盘引擎 | `lib/ziwei/algorithm.ts` 等 | 把用户出生信息变成结构化 `ZiweiChart`（12 宫 + 星曜 + 大限 + 四化 + 农历） | ✅ 已被 chart/cases/chart-compare/heming 页与 AI 解读链路消费 |
| 命理计算 | `patterns.ts`/`radar.ts`/`sihua.ts`/`share.ts` | 格局识别、雷达分、四化映射、真太阳时/表单转换 | ✅ patterns/radar 被组件消费；sihua 仅流年四化被 prompt 层消费，自化/来因宫等**半下线** |
| 领域知识库（数据） | `lib/nihai/`、`lib/ziwei/heming-knowledge.ts`、`famous.ts` | 倪海厦《天纪/人纪/地纪》结构化知识、合盘方法论、名人命盘 | ⚠️ **零页面消费**（纯"知识岛"，为后续功能预留） |
| 古籍原文 + SEO | `lib/classics/`、`lib/seo/knowledge.ts` | 《骨髓赋》《全集》《全书》原文检索；14 主星 × 13 宫位 SEO 内容组织 | ✅ 被 library / knowledge / sitemap 页面消费（但详情内容库为空） |

**最重要的架构事实：排盘不是完全自研。** `algorithm.ts` 的文件头注释写"基于 iztro 开源库"，实际实现是：**调 iztro 的 `astro.bySolar()` 完成安星/五行局/主星/辅星/四化/亮度/大限的全部计算，自研层只做"类型适配 + 结构化增强"**（合并星曜数组、空宫借对宫字段、当前大限标记、农历换算）。`constants.ts` 里残留了一整套自研安星查表（天魁天钺/禄存/天马/主星亮度/纳音五行），但**全仓库无任何 import**——它们是"自研排盘引擎被 iztro 替换"后的历史遗留。

### 3.2 安星流程（谁在算？）

- **iztro 承担全部硬排盘**：命宫/身宫/五行局/紫微位置/十四主星/辅星杂曜/庙旺利陷/年干四化（`mutagen` 字段）/大限宫位与年龄段（`decadal.range`）/身宫。即 `algorithm.ts` 注释所称"基于 iztro 开源库"是**字面真实**。
- **自研层增强**：
  1. 亮度 6 档 → 3 档：`mapBrightness` L31（'庙'|'旺'→bright，'陷'|'不'→dim，'利'|'平'→normal）。
  2. 星曜类型归一：`mapStarType` L45，自建 `SHA_STARS`（12 煞）与 `LUCKY_STARS`（22 吉）黑/白名单 L39-43 兜底 iztro 的 type 字段（主星/煞星/吉星→major/sha/lucky，杂曜→minor）。
  3. 空宫借对宫结构化：`oppositeBranch = (branch+6)%12`，若宫无主星则从对宫拷 `borrowedStars`（只借主星）L122-135——注释自述这是 codex P0 改造，避免文案层从自然语言反查。
  4. 当前大限标记：`currentAge = 今年 - 出生年`（**实岁口径**）L113-120 对 `daXianAge`（iztro 的 **虚岁**口径区间）做区间命中 → **存在 1 岁口径错位风险，见⑤**。
  5. 农历信息由 lunar-javascript 独立计算（不依赖 iztro 返回）L14-28。

### 3.3 真太阳时与子时（share.ts L5-48）

```
calcTrueSolarBranch(clockHour, clockMinute, longitude)   L5-11
  clockMins = hour*60+min
  offset    = (longitude - 120) * 4      ← 每度经度差 4 分钟（东八区基准）
  solar     = (clockMins + offset) mod 1440
  solar ∈ [1380,1440) ∪ [0,60)  → 0（子时 23:00-01:00）
  否则 branch = floor((solar-60)/120)+1
```
- 只做**经度时差**校正，**不含均时差方程（EoT）、不含夏令时**——严格说不是完整真太阳时。
- 晚子时规则（倪师/三合派标准，注释 L13-19）：**23:00-23:59 按次日排盘**。`formToBirthInfo` L26-34 在 `clockHour===23` 时用 `Date(y,m-1,d+1)` 自动跨月/跨年进位。
- `unknownTime`（时辰不详）时固定 `hour=0`（子时）L36-38，**不做 12 时辰概率化**。
- 出生地经度只在选择省份时生效（`longitude: form.province ? form.longitude : undefined` L46）。

## ⑤ 已知坑点 / TODO / 遗留

> 仓库中无字面 TODO/FIXME 标记（已 grep 全 lib/）；坑点多以注释自述与"死代码"形式存在，结合 .workbuddy/memory 整理如下。

**A. 计算口径类（高优先级，直接影响排盘正确性）**
1. **实岁/虚岁错位风险**：`currentAge = 今年-出生年`（algorithm L113-114）是**实岁**，而 `daXianAge` 来自 iztro decadal（**虚岁**区间），L117 直接拿实岁去命中虚岁区间 → 大限起止边界年份可能差 1 岁。需用真实命盘核验（chart 页 L72-73 注释也承认 iztro 大限是虚岁）。当前 `horoscopeDate`（chart 页 L63-77）用 `birthYear+startAge-1` 换算公历年，说明作者知道虚岁口径，但 L114 的 currentAge 没换算，前后矛盾。
2. **晚子时日期进位只看北京时钟 23 点**（share.ts L28），不看真太阳时：`calcTrueSolarBranch` 可能把经度校正后进入子时的钟点（如新疆 22:40 出生，真太阳时已 23:00+）判为子时（hour=0），但日期没 +1 → 排成"当日早子"而非规则注释（L16"23:00-23:59 晚子按次日"）要求的"次日"；反向亦然。正确做法应基于**校正后太阳时 ≥23:00** 决定是否进位。
3. **真太阳时不完整**：只有经度时差 `(经度-120)*4 分钟`，无均时差（EoT）修正、无夏令时处理（share.ts L5-11）。
4. **unknownTime（时辰不详）固定子时**（share.ts L36-38），无"十二时辰穷举/平均"策略——对 AI 解读可能给出误导性确定结论。
