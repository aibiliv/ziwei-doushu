## 1. 范围与职责

「AI 后端与运营层」负责三件事：

1. **AI 解读/对话的 HTTP 出口**：`POST /api/interpret`（命盘维度解读，SSE 流式）、`POST /api/chat`（AI 对话，SSE 流式）——把前端传上来的**本地已排好的 ZiweiChart 文本化**（`buildChartContext`），拼上天纪体系 system prompt，转发给 OpenAI 兼容的 LLM Provider，并把上游 SSE 转成前端协议流式吐出。
2. **收费分层（freemium）闸门**：`plan=free` 走免费 agnes、`plan=deep` 走付费 iztro；deep 路径必须过 `lib/plan.ts` 的订阅/配额闸门，未订阅/耗尽返回 `402 {upgrade:true}`；`GET/POST /api/plan` 做状态查询与 MVP 模拟支付激活。
3. **会话与运营态存储**：服务端维护 AI 对话 chatHistory（最近 20 条）实现无状态多轮；订阅/配额/历史全部落在**文件存储** `.data/plan.json`（MVP，注释明确生产替换为 Postgres 三表 users/subscriptions/usage_logs + NextAuth + 支付 webhook，接口签名保持不变）。

**边界**：排盘算法（`lib/ziwei/*`）、前端 UI（`components/InsightPanel.tsx` 等）不在本层范围，但本文档保留其与本层的**调用契约行号**（见 §3、§9），供 03-前端文档交叉引用。本层**不含**真实鉴权、支付、数据库代码——`pg`/`ioredis` 仅作为依赖躺在 `package.json`，全仓库无一行使用（见 §7）。

## 4. freemium 与配额机制

### 4.1 分层模型（决策史：2026-08-27 iztro 联调 → 08-28 切回 agnes 免费 + 落地分层）

| 层 | tier | 入口 | Provider | 是否限量 | 鉴权点 |
|---|---|---|---|---|---|
| 免费 | free | `/api/interpret` 且 `plan=free` | 非 iztro（agnes 默认，`llm.ts` L55） | 不限量（站点自担成本） | 无 |
| 专业 | pro | `/api/interpret` 且 `plan=deep`、`/api/chat` | 仅 iztro（`llm.ts` L121/L63-66） | 每月 `deepQuota`（默认 100，`plan.ts` L42） | `getPlanState` + `consumeDeep` |

- 前端维度划分（`InsightPanel.tsx` L36-51）：**6 免费** = overview命格总览 / wealth财运 / career事业 / love感情 / personality性格 / health健康；**7 locked（deep）** = siblings兄弟合伙 / children子女 / migration迁移外出 / interpersonal人际贵人 / property田宅 / mentality福德 / parents父母长辈；另有「专项」（四化飞化 advisory）也需 deep（L711-714）。advisory 一旦有解读线程即解锁展示（L891）。
- 服务端不感知“维度”，只认 `plan` 字段（`interpret/route.ts` L85）；维度/文案全在客户端，**前端可改 plan=deep 白嫖 agnes 吗？不能**——deep 强制 iztro（L121），free 强制排除 iztro（L129），客户端无法用 plan 参数把免费流量导到 iztro；但反过来 deep 用户走的是 iztro 而非免费兜底。

### 4.2 402 升级闸门（服务端权威）

- `getPlanState`（`plan.ts` L113-125）：`pro = tier==='pro' && expiresAt>Date.now()`；`remaining = max(0, deepQuota - deepUsedThisMonth)`；`deepAllowed = pro && remaining>0`。
- `interpret` deep 闸：L108 查状态 → 不过则 **402** `{error:'DEEP_NOT_ALLOWED', upgrade:true, tier, remaining}`（L109-119）→ 过则 `consumeDeep`（L120）。
- `chat` 双闸：先 `getPlanState`（L42-48，402 DEEP_NOT_ALLOWED）再 `consumeDeep`（L51-57，402 QUOTA_EXCEEDED）——两闸都返回同构 402 体。
- 前端契约：**任何 `res.status===402` → 弹升级 modal（lockedTopic）**（InsightPanel L761-766、L836-840）；本地 `deepAllowed` 只是启动快照 + 减少无效请求，真实拦截在服务端 402。原 `DEV_BYPASS_LOCKED` 已移除（记忆 2026-08-28）。

### 4.3 配额扣减与存储

- `PlanRecord`（`plan.ts` L29-39）：`tier / deepQuota / deepUsedThisMonth / monthKey / expiresAt / chatHistory / chatSessionId(预留)`。
- **跨月重置**：`monthKey = YYYY-MM`（L44-46）；`getPlanState` 与 `consumeDeep` 各自检测 `monthKey` 不一致即清零已用（L117-121、L154）；`activatePro` 同月续费保留已用、跨月归零（L140）。
- `activatePro(uid, days=30, quota=DEFAULT_DEEP_QUOTA=100)`（L131-146）：直接写 `tier:'pro'` + `expiresAt = now+30d`。
- `consumeDeep`（L149-160）：非 pro / 超 quota → `{ok:false}`；否则 `deepUsedThisMonth += 1` 并全文件写回。
- **扣减时序**：interpret L120 与 chat L51 都是**先扣费再发起 LLM 调用**；调用失败（502）**不退额度**——见 §7.6。
- 数据结构刻意对齐生产三表（文件头注释 L1-13）：`users`(=PlanRecord 主键 uid) / `subscriptions`(tier/expiresAt/quota) / `usage_logs`(deepUsed 明细)。**但没有真正的 usage_log 明细写入**，只有计数器。

### 4.4 chatHistory 服务端维护机制

- 动机：OpenAI 兼容 Chat Completions 是无状态的，多轮靠把历史塞回 `messages`。
- 存于同一 `plan.json` 的 `PlanRecord.chatHistory`，上限 **20 条**（=最近 10 轮 user+assistant，`MAX_CHAT_HISTORY` L62，`appendChatHistory` L75-81 用 `slice(-20)` 截断）。
- 时序（chat/route.ts）：`reset=true` 先清空（L60，前端在换命盘后置位，InsightPanel L677-684）→ 取旧历史 L61 → **先**把本次 user 消息 append（L63，防中途失败丢问题）→ 组消息 L66-71 → 流式结束后经 `onDone` 把完整 assistant 文本 append（L81-87）。因此**每次请求后历史恰好自洽**。
- 已预留 iztro 托管 Session API 迁移位：`getChatSessionId / setChatSessionId`（plan.ts L93-104）。⚠️ 注意：iztro Session 的 `instructions` 字段实测被忽略（记忆 2026-08-27），迁移后仍需 system 消息注入。
- 前端本地不再维护对话轮次，断点刷新后仅剩服务端历史可捞——当前**无「恢复历史」接口**（GET 不返回 chatHistory），刷新即丢 UI，属已知缺口。

## 5. Provider 抽象与回退

### 5.1 抽象设计（`lib/llm.ts`）

- 哲学：**换模型 = 改 .env，零代码**（头注释 L1-18）。全部走 OpenAI 兼容 `/chat/completions`；Anthropic 协议未适配（L17 明示）。
- `getProviders()`（L44-71）：解析 `AI_PROVIDER`（逗号序，默认 `agnes`，L45），逐个 `configOf`——**没配 Key 的 Provider 直接不出现**（L39 `if(!apiKey) return null`）。默认值矩阵：

| name | env Key | baseUrl 默认 | model 默认 | 备注 |
|---|---|---|---|---|
| agnes | `AGNES_API_KEY` | `https://apihub.agnes-ai.cn/v1`（L55） | `agnes-3.0-flash` | 国内域名；海外改 `.com` |
| deepseek | `DEEPSEEK_API_KEY` | `https://api.deepseek.com/v1` | `deepseek-chat` | |
| custom | `CUSTOM_API_KEY` | `https://api.openai.com/v1` | `gpt-4o-mini` | 任意兼容服务 |
| iztro | `IZTRO_API_KEY` | `https://chat-api.iztro.com/v2`（L64） | `iztro-ziwei-v3` | 另设 `maxTokens=4096`（L65） |

- `streamChatCompletion(provider, messages)`（L74-115）：
  - `name==='iztro'` → **委派** `streamIztroChat`（L79-89，异常 catch 后返回 null 供上层回退）；
  - 其余 → `fetch(baseUrl + '/chat/completions')`，`stream:true, temperature:0.7, max_tokens:2048`（L97-103），**HTTP 非 2xx → 打日志返回 null**（L105-109）。
- **回退链在路由层**：interpret L139-144 按 `selected`（即 AI_PROVIDER 顺序）逐个试，拿到 body 即返回。`AI_PROVIDER=agnes,iztro` 时 free 只有 agnes（iztro 被 L129 排除），deep 只有 iztro（非 iztro 被 L121 排除）——两条链互不可达，天然隔离成本。

### 5.2 iztro 专用客户端（`lib/iztro.ts`）

- 端点硬编码 `IZTRO_BASE = 'https://chat-api.iztro.com/v2'`（L42），client 只用 `process.env.IZTRO_API_KEY`（L70/87）。**`IZTRO_BASE_URL` 在 llm.ts L64 被读入 ProviderConfig 但 iztro 客户端根本不消费 → 该 env 配置无效（坑，见 §7.4）**。
- `buildBody`（L54-66）：默认 `model='iztro-ziwei-v3'`、`language='zh'`、`max_tokens=4096`；可选 `reasoning_effort` / `enable_iztro_call=false` / 奇门 `metadata.current_datetime`（L24-25、L62-64，奇门 qimen 路径已留参数但未接路由）。
- **不发送 `temperature`**（头注释 L78：避免触发拒收）；流式真逐 token（记忆 2026-08-27 实测，非整段）。
- `streamIztroChat`（L69-83）：`fetch` 后 `!res.ok` 抛 `IztroError`（含截断 300 字符响应体，L78-81）；成功**原样返回上游 OpenAI SSE Response**，由上层 `buildTransformStream` 做协议转换。
- `iztroChat` 非流式（L86-105）：返回 `text / iztro_tools[] / usage / billing.balance_after_cny`（L99-105）——**成本与余额回传字段已就绪但当前路由未记录**（生产 usage_logs 素材）。
- 鉴权/模型/成本特性在代码中的体现：Bearer Key（L75/92）；system 角色提示生效、`metadata.system_prompt_override` 与 Session `instructions` 被忽略（文件头 L10 实测结论）；必须带阳历生日+时辰+性别（否则 mingpan 无法计算）→ 已由 `buildChartContext` 保证（prompt.ts L35，见记忆 2026-08-27）；单次 ≈12.9k 输入 token ≈ ¥0.015（头注释 L12）→ 这就是 chat/deep 每次扣 1 额度的成本依据（100 次/月 ≈ ¥1.5 的模型成本口径）。

### 5.3 Prompt 组装（`lib/prompt.ts`）

- `buildSystemPrompt`（L9-24）：倪海厦《天纪》南派三合派立场；**动态注入当前日期**（模型 cutoff 2025，必须显式告知“今年=2026”，L10-16）；四化固定不动、不用飞星（L20）；【小标题】分段规范（L21）；免责声明（L22）。

## 6. SSE 实现细节

- 协议转换（`lib/sse.ts`）：
  - 上游 OpenAI：`data: {"choices":[{"delta":{"content":"..."}}]}`、收尾 `data: [DONE]`（L2-4）。
  - 下游前端协议：`data: {"delta":{"text":"..."}}\n\n` + 收尾 `data: [DONE]\n\n`（L48-50、L56）。
- `SSE_HEADERS`（L7-11）：`text/event-stream` + `no-cache, no-transform`（no-transform 防中间代理缓冲/改写压缩破坏流）+ keep-alive。
- `buildTransformStream`（L18-65）：
  - 行缓冲 `buf += decoder.decode(value,{stream:true})` 后 `split('\n')`，**最后一个不完整行留待下包拼接**（L31-36）——防 TCP 分包把 data 行切断；
  - 只认 `data:` 前缀（L39）；`[DONE]` 跳过（L41，由 finally 统一补发下游 `[DONE]` L56）；JSON 解析失败静默忽略（L52）；
  - 累加 `fullText`，每个 delta 触发 `onDelta`（L46-47）；
  - **`finally` 里：enqueue 下游 `[DONE]` + close + `onDone(fullText)`**（L55-59）——chat 路由借此把整段 assistant 落库（chat/route.ts L81-87）；
  - `cancel()` 反向 `reader.cancel()` 上游（L61-63）——客户端中断时尽量释放上游连接。
- mock 流（interpret L63-78）：无 Key 时把 mock 文案切成 6 字符块、25ms 间隔模拟流式（开发调试用）。

## 7. 已知坑点 / TODO / 遗留

> 代码内显式 TODO/FIXME 极少；风险主要藏在注释的 ⚠️、决策记忆与实现细节里。以下按严重度排序。

### 7.1 生产阻断级（上线前必修）
1. **无鉴权，uid 完全可伪造**：三路由全部信任 `body.uid`（interpret L86 / chat L29 / plan L21），`POST /api/plan {uid:任意}` 即可把任意 uid 激活成 pro（plan/route.ts L5 ⚠️ 自述 MVP）；chat/interpret 的 402 闸门可被“自激活”绕过。生产须 NextAuth session 取 uid + 支付 webhook 激活（plan.ts L128-129、plan/route.ts L6-7 均已注释）。
2. **文件存储不能上生产**：`.data/plan.json` 全量读改写（plan.ts L48-60）——(a) serverless（Vercel / `build:cf` next-on-pages 目标）文件系统**只读/非持久/每实例独立**；(b) 读-改-写非原子，**并发请求会丢更新/超卖额度**（getPlanState 与 consumeDeep 各自 readAll，TOCTOU）；(c) O(全用户) 每次请求全量序列化。pg 依赖已装（package.json L27），ioredis L22 可作锁/缓存。
3. **chat/interpret 先扣费后调用，失败不退**：chat L51 扣费 → L75 调用，502 `CHAT_FAILED` 不退款（L90-96）；interpret deep 同样 L120 扣费后才检查 iztro 是否配置——**未配 iztro 时用户被扣额度后收到 502**（L121-127）。生产要 pending→结算或失败退费。
4. **iztro Key 泄露史**：记忆 2026-08-27「Key 曾出现在聊天中，建议去 platform.iztro.com/console 轮换一次」——上线前必须轮换。

### 7.2 安全/成本敞口
5. **free 路径无限量**：agnes 解读不设防，匿名可刷（每命盘多维度 × 多次），token 成本站点自担；无速率限制、无 chart 大小/合法性校验（chart 全由客户端传入）。
6. **`uid` 缺省为 `'anonymous'`**：interpret L86 / chat L29——不带 uid 的客户端（如 ChatPanel.tsx L47 不发 uid）所有访客**共享同一条 anonymous 配额记录**；若有人激活 anonymous，等于全站共享 pro。InsightPanel 会生成 zw_uid 规避，但旧入口 ChatPanel 不会。
7. **客户端可注入任意 messages**：`...messages` 直接拼入（interpret L96），免费/付费都是“提示注入”敞口；system prompt 是唯一防线。

### 7.3 配置/文档缺口
8. `.env.example` **缺 IZTRO_\* 整段**（只有 AI_PROVIDER/AGNES/DEEPSEEK/CUSTOM，L5-20），且默认 `AI_PROVIDER=agnes,deepseek` 与线上实际 `agnes,iztro` 不一致——新环境按 example 配会“deep 永远 502/没配额可用”。
9. `IZTRO_BASE_URL` 形同虚设：llm.ts L64 读取，iztro.ts L42/L73 硬编码 base——改 env 不生效，纯误导（见 §5.2）。
10. 记忆 2026-08-27：iztro `metadata.system_prompt_override` 与 Session `instructions` **被静默忽略**，勿在迁移 Session API 时依赖（plan.ts L37-38 的 chatSessionId 预留只是存 id）。

### 7.4 逻辑/边界坑
11. **mock 降级仅当“一个 Provider 都没配”**（interpret L100-103）：若只配了 iztro 且 plan=free → iztro 被 L129 排除 → 直接 502（L130-135），无 mock、无兜底。
12. interpret 的**历史消息会被逐轮带入**（L96）：ChatPanel 每次把累积 messages 全量上送（L47）→ 长对话后 prompt 越来越大、重复计费输入 token；InsightPanel 单维度单轮则无此问题。
13. chat 无 Provider 回退链：硬编码 iztro（L75），iztro 宕机即 502（无 agnes 兜底），与 interpret 的回退设计不对称。
14. **客户端中断的落库不确定性**：chat 的 assistant 靠 onDone 落库（L81-87），而 onDone 在流 `finally` 触发（sse.ts L55-59）；若前端 abort → `cancel()` 取消上游（sse.ts L61-63），start 协程在已取消流上继续执行，**部分场景下 assistant 可能不落库**（刷新后历史不完整）。正常走完则无虞。
15. `deepAllowed` 是前端**启动快照**（InsightPanel L647-653），跨月/过期/他端激活后不刷新，直到 reload；服务端 402 才是权威（设计上 OK，但 UX 上配额耗尽提示依赖 402 弹窗）。
16. `next.config.js` 无任何 rewrite/proxy/安全头配置；三路由未声明 `runtime`（默认 nodejs），未做 body 大小限制。
17. `history.ts`（前端 localStorage 命盘历史）与 `plan.json` 的 chatHistory 是**两套互不相通的历史**；`chatSessionId` 预留字段目前无人读写。

## 8. 二开扩展点建议

### 8.1 生产化改造清单（按依赖序）
1. **数据层**：`lib/plan.ts` 四个核心接口（`getPlanState/activatePro/consumeDeep` + chatHistory CRUD + sessionId）换 pg 实现，**保持签名不变**（文件头注释 L1-13 明示设计意图），建 users/subscriptions/usage_logs 三表；`consumeDeep` 用单条 `UPDATE … SET used=used+1 WHERE used<quota AND expires_at>now() RETURNING` 原子扣减 + 事务，消灭 §7.1-2 竞态；chatHistory 独立表/列，SQL 层做 `ORDER BY … LIMIT 20`。
2. **鉴权**：接 NextAuth（依赖未装），所有路由从 session 取 uid；`POST /api/plan` 从“直开”改为 webhook 端点（Stripe/微信验签 → `activatePro`），并把 `activatePro` 从公开可调变为服务端内部调用。
3. **计费闭环**：usage_logs 记录每次 deep 消耗（uid/model/token/成本/结果）；把 iztro 响应里的 `usage` 与 `billing.balance_after_cny`（iztro.ts L30-40/L104）落库做成本看板；失败退费（pending→confirm）。
4. **chat 加固**：补 provider 回退（与 interpret 同构：iztro 失败降 agnes/报错但退费）；支持“恢复历史”GET（刷新后可续聊）；SSE 断连时 onDone 兜底落库。
5. **配置收口**：`.env.example` 补 IZTRO_\* 段并更新默认 `AI_PROVIDER=agnes,iztro`；修 `IZTRO_BASE_URL` 失效（iztro.ts 改用可配置 base）或删除该 env 读取；轮换 iztro Key。
6. **防滥用**：free 路径加频率限制/IP 维度限流；chart/message 长度校验；`uid` 缺省值从共享 `'anonymous'` 改为必填（或服务端按会话生成）。
7. **部署适配**：若走 `build:cf`/Vercel，文件存储方案须整体替换（pg + ioredis 已备）；SSE 确认平台无缓冲层问题（已设 no-transform）。

### 8.2 新增 Provider / 模型
- **同一 OpenAI 协议**：只动 `lib/llm.ts` `getProviders` 的 switch（L53-67）+ `.env.example`，零路由改动（头注释 L15 明示该设计）。
- **非 OpenAI 协议（如 Claude）**：`streamChatCompletion`（llm.ts L74）加分支；`@anthropic-ai/sdk` 已在 package.json（L14）——疑似为 Claude 预留但从未使用，可直接用。
- **iztro 奇门**：路由里把 `streamIztroChat` 的 opts 换成 `{model:'iztro-qimen-v3', currentDatetime: <ISO8601>}`（iztro.ts L24-25/L62-64 已支持），需新增前端入口与计价策略。

### 8.3 运营/产品功能接入点
- **新深度维度**：前端 `TOPICS` 数组加 `{key,label,locked:true}` + `TOPIC_PROMPTS` 文案（InsightPanel L36-51/L53+），后端 interpret **零改动**（只认 plan=deep）。
