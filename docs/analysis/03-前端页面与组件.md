## 1. 范围与职责

前端层由三块组成，职责边界如下：

1. **页面路由层（`app/`）**：首页营销长页（`/`）、排盘工作台（`/chart`）、合盘（`/heming`）、名人案例（`/cases`）、盘面对比（`/chart-compare`）、卷轴开场预览（`/preview`）、古籍阅读器（`/library` 系列，SSR/静态）、知识百科（`/knowledge` 系列，SSR SEO 落地页）、条款/隐私、`layout.tsx`（根布局 + 主题注入）、`sitemap.ts`/`robots.ts`。
2. **主题体系**：`globals.css`（2.0 CSS Token：`--bg-*`/`--tx-*`/`--ac` + 旧 `--t-*` 令牌兼容层 + 图表页布局类）、`iztro-themes.css`（react-iztro 星盘 4 套 CSS 变量主题覆盖）、`components/ThemeProvider.tsx`（dark/light React Context + localStorage `ziwei-theme`）。
3. **组件层（`components/`，20 个）**：两套并行的"命盘渲染"路线——A) 官方 **react-iztro `Iztrolabe`** 组件（/chart、/cases、/chart-compare 使用）+ 外围自制组件（TimeNav、DaXianYearNav、SanFangOverlay、PatternsCard、InsightPanel、StarDetailPanel、LangSelect）；B) **自绘盘面** ChartBoard/PalaceCell（只有 /chart-compare 左栏在用，属 P0 验证产物）。

**与 02 文档的分界**：AI 后端路由与 lib/llm、lib/iztro、lib/plan 属「AI 后端与运营层」（见 02）；本文档只描述前端如何消费它们（SSE fetch 契约见 §6），并覆盖前端独享的 `lib/ziwei/history.ts`（localStorage 历史）、`lib/seo/knowledge.ts`（SEO 数据装配）、`lib/classics`（古籍数据）。

**关键总体判断（先读）**：
- **无全局状态库、无 i18n 框架、无路由级数据请求**。除主题 Context 外全部是页面级 `useState` + props 下钻；排盘在浏览器端同步执行（`generateChart`）或由 react-iztro 组件自算；"后端"只在 AI 解读/对话/订阅三处被 fetch（§6）。
- **`iztro-hook` 已声明依赖但全仓库零引用**（仅 package.json/pnpm-lock）；`useChat`（AI SDK）不存在。SSE 解析是手写 `ReadableStream` + `sseBuffer` 拼行。
- **存在 4 个"孤儿组件"**（无人 import）：ChatPanel、ChartSummary、ShareModal、ShareCardCanvas、FamousPersonCard —— 是旧版/规划版产物，改版时可直接复用或删除（§4.7）。
- **`/heming` 页面调用的 `/api/generate`、`/api/heming` 两个接口在当前仓库 app/api 下不存在**（仅 plan/interpret/chat 三条路由），点击合盘会 404 失败——前端已写好、后端路由未落地（§7.5）。
- 本仓库的 `lib/ziwei/db-analysis.ts` 是**开源占位版**（STAR_DB 置空），导致 `/knowledge/[star]/[topic]` 的 182 个 SEO 落地页生成 **0** 条静态路由、访问即 404；`/sitemap.xml` 同样不会收录这些详情页（§3.10、§7.6）。

### 6.2 iztro-themes.css（139 行）——react-iztro 主题覆盖机制

react-iztro 星盘内部用 `--iztro-color-*` 系列 CSS 变量渲染；本文件用**类名作用域 + 变量覆盖**不动组件源码：

### 6.3 ThemeProvider 主题切换全链路

1. `layout.tsx` head 内联脚本：首帧同步 `data-theme`（防 FOUC，默认 dark）。
2. `ThemeProvider`（client，59 行）：首帧 state 固定 'dark'（**防 SSR hydration mismatch**——注释明确：依赖 theme 的 inline style 组件如 BirthForm 在 SSR/hydration 首帧必须一致）；mount 后从 localStorage/html 属性恢复；`toggle()` 加 `.theme-transitioning` 类 420ms（过渡期由全局 CSS 控制渐变）。
3. 消费面：`useTheme()` 被首页/heming/BirthForm/StarField 等引用做 **JS 分支 inline style**；纯 CSS 变量组件自动换肤。
4. **三套并存**：a) CSS 变量（--t-*/--bg-*）；b) React state inline 颜色（首页 useColors、BirthForm isDark、heming cardStyle）；c) react-iztro 盘面变量主题（theme-metis 是固定白卡风，**不随 dark/light 切换**——盘面在暗色主题下仍是白底卡片，视觉上是"盘中白卡 + 页面暗底"，属设计选择）。
